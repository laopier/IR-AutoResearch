# IR-drop AutoResearch 实验规则

## 1. 研究目标

在固定数据、评价器和计算预算下，由 agent 修改 MAVI 的模型结构、优化器、损失函数或训练逻辑，寻找更好的 IR-drop 预测方案。

当前阶段的目标是建立可运行、可比较、可回滚的研究闭环，不声称已经获得优于论文或官方基线的结果。

## 2. 目录权限

### Agent 可以修改

- `train/mavi.py`
  - 模型结构
  - 前向传播
  - 可训练模块
- `train/experiment.py`
  - 参数初始化
  - 优化器
  - 学习率调度器
  - 损失函数
  - 单步训练逻辑

### Agent 不得修改

- `prepare/`
  - 数据读取
  - train/validation 划分
  - 评价指标
- `program/`
  - 实验预算
  - 实验流程
  - 结果记录规则
- `tests/`
  - 接口与数值健康检查
- 已经生成的固定 manifest

### 只允许追加

- `results/`
  - 不覆盖或删除历史实验记录
  - 每次实验使用新的结果文件名

## 3. 数据隔离

### Train

agent 可以通过训练接口使用训练数据和标签。

### Validation

validation 只由 `program/runner.py` 评价。

agent 可以看到 validation 指标，但不得：

- 把 validation 样本加入训练；
- 使用 validation 标签反向传播；
- 根据 validation 样本单独编写特例；
- 使用 validation 数据计算训练归一化统计量。

### Test

test 在搜索阶段必须保持隐藏。

test 不得用于：

- 选择模型；
- 调整超参数；
- 设计损失函数；
- 选择 checkpoint；
- 决定是否保留某次修改。

只有在人类确认候选方案后，才能运行最终 test。

## 4. 公平比较

同一轮候选方案与基线必须使用相同的：

- train manifest；
- validation manifest；
- 随机种子；
- 训练步数；
- batch size；
- 数据顺序规则；
- 硬件类型；
-评价器；
- 预训练条件。

官方 checkpoint 只用于兼容性检查或参考推理，不得与从随机初始化训练的候选模型直接比较并宣称更优。

## 5. 实验版本管理

每次正式实验必须对应一个明确的 Git commit。

实验开始前：

1. 完成一项明确修改；
2. 运行全部测试；
3. 提交代码；
4. 确认工作区 clean；
5. 启动实验。

结果文件必须记录：

- Git commit；
- 工作区是否 dirty；
- 修改目的；
- seed；
- 数据 manifest 及其 SHA256；
- 训练预算；
- validation 指标；
- 参数量；
- 运行时间；
- 峰值显存。

不得只保留“最好”的代码。失败实验及其结果也应保留，以避免重复尝试，并为后续分析提供依据。

## 6. 指标使用

每次 validation 至少记录：

- `mae_float`：原始浮点 MAE，越低越好；
- `nrms_official`：CircuitNet 兼容 NRMS，越低越好；
- `ssim_official`：CircuitNet 兼容 SSIM，越高越好；
- 运行时间；
- 峰值显存；
- 参数量。

不得仅凭单一指标宣布方案更优。

探索阶段以 `mae_float` 作为主要搜索信号，同时检查 NRMS、SSIM 和资源消耗是否明显退化。

具体容忍阈值应由正式 baseline 结果确定，不能依据当前 mini smoke 指标制定。

## 7. 分阶段随机种子策略

### 探索阶段

- 使用一个固定 seed；
- 快速排除明显失败的方案；
- 不对每次修改运行多随机种子，以控制算力成本。

### 候选确认阶段

只有表现稳定且有明确改进的候选方案，才使用至少 3 个固定 seed 重新训练。

需要报告：

- 各 seed 的结果；
- 平均值；
- 标准差；
- 是否每个 seed 都优于基线。

不得只报告最好的 seed。

## 8. 实验结果分类

### Smoke

只验证工程链路能够运行，不用于比较性能。

### Search

在固定的缩减预算下比较候选方案，用于筛选研究方向。

### Confirmation

对少量候选方案使用更完整预算和多个 seed。

### Final test

由人类明确批准后，对最终候选方案运行隐藏 test。

## 9. 修改原则

每轮实验应尽量只验证一个主要假设，例如：

- 修改特征融合方式；
- 加入残差连接；
- 修改损失函数；
- 修改优化器；
- 修改学习率计划。

如果同时修改过多内容，即使结果变好，也难以判断改进来自哪里。

每条实验描述至少回答：

1. 改了什么？
2. 为什么可能有效？
3. 与上一版本相比只改变了哪些变量？
4. 结果支持还是反驳了该假设？

## 10. 当前限制

当前 mini 数据仅用于 smoke：

- 样本数量过少；
- 不代表正式 train/validation 分布；
- 不能用于论文级性能比较；
- 不能证明模型泛化能力。

正式 AutoResearch 搜索开始前，还需要：

1. 获得完整 N28 训练数据；
2. 使用固定 train/validation manifest；
3. 跑出随机初始化 MAVI baseline；
4. 确定正式训练预算；
5. 根据 baseline 确定质量与资源容忍阈值。
