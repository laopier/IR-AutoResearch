# SA0：IR-drop 小数据研究学习任务（第一版）

本文借鉴 thermal-autoresearch 的任务组织与研究过程，按本项目的目标、指标和资源重新定义。本文件是学习阶段的任务说明，尚未接入现有 SA0 runner，也不代表已完成正式 SA0 实验。

## 研究目标

以当前 MAVI 模型及其训练配置作为冻结的基线。在相同数据划分、预处理、评价口径和预先规定的预算下，探索模型或训练配置的改进，形成可复现、可审查的实验记录。

本轮只研究初始学习率。候选相对于固定基线，MAE 严格降低、NRMS 不升、SSIM 不降，且未超出资源限制时，才满足保留条件。一次候选胜出只支持当前实验条件下的结论，不代表完整数据上的改进或跨 seed 的稳定优势。

## 当前实验约定

- 模型：当前 MAVI；模型结构保持固定。
- 数据根目录：`/mnt/d/WSL/Project/CircuitNet-main/training_set_full_mini/IR_drop`。
- 训练清单：`prepare/manifests/smoke_train.csv`。
- 验证清单：`prepare/manifests/smoke_validation.csv`。
- 训练预算：每次从头训练 100 次参数更新，batch size 为 2。
- seed：0；训练 DataLoader 的独立 generator 同样设为 0。
- 训练 DataLoader：shuffle=True，drop_last=True，num_workers=0。
- 验证 DataLoader：batch size 为 1，shuffle=False，drop_last=False。
- 学习率：余弦调度，horizon 为 200000，最低学习率为 1e-7；每次参数更新前设置学习率。
- 基线初始学习率：2e-4；当前候选初始学习率：1e-4。
- 比较 checkpoint：第 100 步，不按中间验证结果选择最佳 checkpoint。
- 运行环境：相同本地 GPU 和 Python 环境，双方采用相同启动方式；记录实际环境与命令。
- 本轮最多评估三个候选；失败或中断的尝试也记入实验与成本记录。

## 实验前读取的材料

读取基线的模型与训练配置、数据和评价约定、验证指标、可取得的训练日志、资源记录以及历史候选记录。明确记录缺失信息，不得编造训练曲线、原因、计时或实验结果。

固定基线始终保持冻结。历史候选可作为提出新假设的依据，但不得用新候选替换基线来改变保留门槛。若多个候选均满足门槛，报告各自指标和成本，不自行修改评价规则。

## 研究过程

1. 根据已有证据提出三个假设。每个假设包含：观察依据、可能机制、具体修改、预期结果、风险和结论适用范围。
2. 选一个假设进行实验并说明理由。先记录假设和实验条件，再修改代码；每轮仅改变一个明确的研究因素。
3. 记录实际配置与代码版本，从头初始化模型、优化器与随机状态，按照统一预算训练和验证。
4. 与固定基线比较验证指标及资源消耗，按既定规则决定保留或回退。
5. 分析结果并修订下一轮假设。连续三轮没有有用进展时，重新审视研究方向；不能据此延长预算。

当前学习阶段由用户逐步实现和运行代码，agent 提供解释、审查与小步骤指导，不跳过学习过程直接替用户完成整套实现。以后切换为自主执行时，需要另行明确执行接口、可修改文件和资源上限。

## 评价与决定

对完成训练与验证的候选，仅在以下条件全部满足时保留：

- candidate MAE < baseline MAE；
- candidate NRMS <= baseline NRMS；
- candidate SSIM >= baseline SSIM；
- 满足预先规定的资源限制和固定实验约定。

按完整精度的结果比较，不使用显示时四舍五入后的数字。不在看到候选结果后临时更改门槛。若指标出现取舍，记录具体改善与退化，并按原规则回退。

训练 loss 用于观察优化过程、震荡和异常，不作为候选保留依据。训练 loss 下降不证明验证表现改善，也不能识别验证集上的最佳 checkpoint。

程序错误、显存不足和中断属于未完成的实验，单独记录；这些事件不能证明研究假设被否定。回退修改时保留实验记录。

## 修改边界

不得修改数据内容、训练与验证划分、输入特征与标签定义、预处理或指标实现。不得将验证数据用于梯度更新，不得修改预算执行、计时与显存统计、结果记录或保留/回退规则。不得在开发阶段利用保留测试集进行调参。

当前仅允许修改初始学习率。模型、损失函数、优化器其他参数、batch size、训练步数、学习率调度周期及其余配置保持固定。未来如开放模型模块修改，先明确新的授权范围与实验约定，再开始对应实验。

## 每轮记录

- 实验标识、假设、依据与预期结果。
- 修改内容、代码版本或源码快照、完整配置和运行命令。
- seed、数据清单及其版本或校验值。
- 初始与最终验证指标，以及相对于固定基线的差值。
- 可取得的逐步训练日志、训练耗时、峰值显存和失败尝试的成本。
- 执行状态、保留或回退决定及其依据。
- 观察事实、未验证的可能原因、结论边界和下一轮建议。

分析时间、训练时间和 GPU 分配时间分别记账，不混为一项。当前 training_seconds 包含训练循环内取数据、数据传输和日志输出等耗时，不包含初始或最终验证；双方使用相同计时边界。无法测量的时间明确标记，不倒推或编造。

## 停止与交付

达到候选次数或已确定的资源预算上限时，停止新实验，整理现有证据。新假设可作为后续建议，不在预算耗尽后继续执行。

交付固定基线、全部候选的配置与结果、实验历史、资源记录及保留/回退理由。保留候选应提供代码、配置与对应 checkpoint；缺失产物明确说明。

如果没有候选满足保留条件，明确报告本轮未找到胜出的候选，保留固定基线，并给出有证据支持的后续建议。不得将“未超过基线”包装成成功。

本轮为小数据、单 seed、100 步学习实验。正式研究需另行确定数据规模、训练和搜索预算，并报告独立运行的波动；不得用本轮结果替代正式研究结论。
